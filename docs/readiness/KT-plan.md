# Knowledge-transfer and handover plan

Sessions should cover architecture and trust boundaries; local/test/staging/production setup; migrations; configuration and secret ownership; auth/RBAC; data model and FPO traceability; backup/restore; provider failure; Packet 13 operations; monitoring; release/rollback; and known gaps.

Handover checklist: repository access, environment ownership, domains/TLS, provider accounts, database, Redis, object storage, monitoring, runbooks, legal contacts, support escalation and open risks. Use role names, not invented staff names. The receiving team signs the checklist only after running the staging smoke and restore rehearsals.
